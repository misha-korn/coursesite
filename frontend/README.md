# CourseSite Frontend

Фронтенд для API из этого репозитория. React 19, Vite, Tailwind CSS 4, React Router 7.
Бэкенд не тронут ни одной строкой: фронтенд общается с ним только по HTTP.

## Запуск

Сначала подними бэкенд (он должен слушать `localhost:8000`):

```bash
docker compose up -d
```

Потом фронтенд:

```bash
cd frontend
cp .env.example .env
npm install
npm run dev
```

Открывай http://localhost:5173

Внимание: с первого раза каталог не загрузится, в консоли будет ошибка CORS.
Так и задумано. Фронтенд ходит напрямую на `localhost:8000`, а это другой origin,
поэтому браузер требует, чтобы сервер разрешил такие запросы. Что делать, написано
ниже в разделе «Настройка CORS».

## Настройка CORS

Проблема: страница открыта на `http://localhost:5173`, а запрос уходит на
`http://localhost:8000`. Порт разный, значит для браузера это чужой сервер. По
умолчанию браузер не даёт JavaScript читать такие ответы.

Важно понимать: запрос до Django доходит и обрабатывается, блокируется именно
чтение ответа на стороне браузера. Тот же запрос из curl или Postman пройдёт без
проблем, потому что они не браузеры и политику CORS не применяют.

Решает это пакет `django-cors-headers`: он добавляет в ответ заголовок
`Access-Control-Allow-Origin` с адресами, которым можно доверять.

Что нужно сделать на бэкенде:

1. Поставить пакет `django-cors-headers`.
2. Добавить `corsheaders` в `INSTALLED_APPS`.
3. Добавить `corsheaders.middleware.CorsMiddleware` в `MIDDLEWARE`, и обязательно
   выше `CommonMiddleware`.
4. Прописать список разрешённых адресов в `CORS_ALLOWED_ORIGINS`, куда входит
   `http://localhost:5173`.

Проверять удобно во вкладке Network: перед POST-запросом браузер сам отправляет
служебный запрос методом OPTIONS (он называется preflight), и на него сервер тоже
должен ответить разрешающими заголовками. Если preflight красный, значит middleware
стоит не на своём месте или адрес не попал в список.

Ставить `CORS_ALLOW_ALL_ORIGINS = True` не нужно: это разрешает доступ вообще
всем сайтам.

Альтернатива, при которой CORS не нужен вовсе: спрятать фронтенд и API за один
адрес. Именно так делается в проде через nginx, а в разработке для этого есть
прокси в Vite. Здесь он отключён намеренно, чтобы разобраться с CORS вручную.

## Что умеет

Гость: главная, каталог с поиском, фильтрами по категории и цене, сортировкой и
пагинацией, страница курса с программой и отзывами, регистрация и вход.

Студент: покупка курса с переходом на страницу оплаты, «Мои курсы» с прогрессом,
страница урока с видео и отметкой о прохождении, сертификаты, отзыв на купленный курс.

Преподаватель: список своих курсов вместе с черновиками, создание и редактирование
курса, публикация, добавление и удаление уроков.

## Языки

Русский, английский, испанский. Переключатель в шапке, выбор сохраняется в браузере.
При первом заходе язык берётся из настроек браузера.

Чтобы добавить язык: скопируй `src/i18n/ru.js`, переведи значения, импортируй файл в
`src/i18n/index.jsx` и добавь в объект `DICTIONARIES`. Больше ничего менять не нужно.

Переводы сделаны небольшим контекстом на 40 строк, без библиотеки. В большом проекте
взяли бы `react-i18next`, здесь это лишняя зависимость.

## Структура

```
src/
  api/client.js        обёртка над fetch: JWT, автообновление access, разбор ошибок DRF
  context/AuthContext  текущий пользователь, вход, регистрация, выход
  i18n/                словари и переключатель языка
  hooks/               useCategories с кэшем на время сессии
  components/          Layout, CourseCard, ProtectedRoute и мелкие UI-кирпичики
  pages/               по файлу на страницу
```

## Как устроена авторизация

При входе бэкенд отдаёт пару токенов, они лежат в `localStorage`. К каждому запросу
подставляется `Authorization: Bearer <access>`. Если сервер отвечает 401, клиент один
раз пробует обновить access через `/api/auth/refresh/` и повторяет запрос. Если refresh
тоже мёртв, токены стираются и пользователь считается гостем.

Хранение в `localStorage` уязвимо к XSS. Более защищённый вариант это httpOnly cookie,
но тогда возвращается необходимость в CSRF-защите. Для учебного проекта выбран первый
вариант как более простой.

## Известные ограничения

API отдаёт автора курса и студента в отзыве числовым id, эндпоинта для получения
профиля чужого пользователя нет. Поэтому вместо имени автора показывается его id.
Если добавишь на бэкенде вложенный сериализатор автора, тут понадобится поправить
`CourseDetail.jsx` и `CourseCard.jsx`.

Обложек у курсов в модели нет, поэтому карточки рисуют цветную заглушку с первой
буквой названия. Цвет стабильный, зависит от id курса.

В настройках DRF не включён `page_size_query_param`, поэтому список категорий
приходит первыми двадцатью. Если категорий будет больше, добавь параметр на бэкенде.

## Сборка для прода

```bash
npm run build
```

Результат кладётся в `frontend/dist`. Дальше эту папку отдаёт nginx как статику, а
`/api/` проксирует на Django. В `nginx.conf` для этого нужен блок:

```nginx
location / {
    root /app/frontend;
    try_files $uri $uri/ /index.html;
}
```

Строка `try_files` обязательна: маршруты вроде `/catalog` существуют только в браузере,
на диске таких файлов нет, и без неё обновление страницы даст 404.
